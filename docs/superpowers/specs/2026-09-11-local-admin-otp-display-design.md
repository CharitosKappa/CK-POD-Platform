# Local admin OTP display

## Purpose

Make local staff sign-in usable without reading server logs while preserving the production passwordless authentication boundary.

## Approved behavior

- The generated six-digit staff OTP is returned by `POST /api/admin/auth/request-code` only when `APP_ENV=local` and `NODE_ENV` is not `production`.
- The code remains genuinely one-time, expires after ten minutes, retains the existing attempt limits, and is regenerated by **Resend code**.
- The admin sign-in screen displays the current development code in a quiet, clearly labelled “Local development code” notice on the verification step.
- The code can be copied or entered normally; it is not automatically submitted.
- A fixed password or bypass path will not be introduced.

## Security boundary

- Production and any non-local application environment continue returning only `{ ok: true }` from code requests.
- The API uses the parsed server environment rather than a browser-supplied flag.
- Unknown or uninvited staff emails keep the non-enumerating response and never receive a development code.
- Raw code storage does not change: the database retains only the existing hash. The raw code exists only for the request lifecycle and the local response.
- No email provider credentials, hashes, session tokens, or membership details are exposed.

## Implementation shape

`StaffIdentityService.requestCode` returns the generated code only when an eligible staff member or configured bootstrap owner exists. The admin request-code route conditionally includes that value as `developmentCode` under the server-owned local guard. The sign-in form reads the optional field, displays it on the code stage, refreshes it after resend, and clears it when changing email or completing authentication.

## Validation

- Domain tests verify eligible and ineligible return values without weakening challenge behavior.
- Route-level logic verifies that only the exact local/non-production combination can expose the optional field.
- UI type checking verifies the optional response shape and code-stage rendering.
- Format, lint, typecheck, focused tests, and production build must pass.
